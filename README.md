# SanghaTelangana — Buddhist Digital Heritage Platform (Stage 2)

SanghaTelangana is a digital heritage web application dedicated to documenting, archiving, and showcasing the ancient Buddhist heritage of Telangana (Phanigiri, Nelakondapalli, Kotilingala, Dhulikatta, Chandavaram, and Nagarjunakonda).

---

## 1. Supabase Environment Variables

The application connects to **Supabase** (PostgreSQL database, Authentication, and Storage) via two client-side environment variables defined in `.env`:

```env
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.your-anon-key-here
```

### What these variables are:
* **`VITE_SUPABASE_URL`**: Your Supabase project's unique HTTPS REST and API endpoint (e.g., `https://abcdefghijklm.supabase.co`).
* **`VITE_SUPABASE_ANON_KEY`**: The client-side **anonymous (public)** API key generated by Supabase. This key is safe to use in browser applications because Row Level Security (RLS) policies enforce database access control on the server.

> **Note:** SanghaTelangana includes an **integrated dual-mode sandbox engine**. If these values are left empty or contain placeholder values, the app will continue to run seamlessly with full local database state, auth sessions, role switching, and local storage fallback. Once real keys are provided, it automatically connects to your live Supabase cloud project.

## 2. Step-by-Step: How to Create Your Supabase Project & Get Credentials

Follow these steps to set up your live cloud database in under 2 minutes:

### Step 1: Create a Free Account & Project
1. Navigate to **[https://supabase.com](https://supabase.com)** and click **Start your project** (or sign in with GitHub/Google).
2. Click **New Project**.
3. Choose an organization, enter a name (e.g., `SanghaTelangana`), set a secure database password, and select a region near your users (e.g., `South Asia (Mumbai)`).
4. Click **Create new project** and wait ~1–2 minutes for the database to provision.

### Step 2: Retrieve API Keys
1. In your Supabase project dashboard, navigate to **Project Settings** (gear icon in the sidebar) > **API**.
2. Under **Project URL**, copy the `URL` (e.g., `https://your-id.supabase.co`).
3. Under **Project API keys**, copy the `anon` / `public` key string.

### Step 3: Apply the Keys to SanghaTelangana
Open the `.env` file in the project root and replace the placeholders:

```env
VITE_SUPABASE_URL=https://your-actual-id.supabase.co
VITE_SUPABASE_ANON_KEY=your-actual-anon-key
```

Or configure them in Google AI Studio via the **Settings / Secrets** panel.

## 3. Database Schema & Seed Data Migration

We have prepared the complete SQL definitions ready to execute in your Supabase SQL Editor.

### Step 1: Run the Schema & RLS Policies
1. In your Supabase dashboard, click on the **SQL Editor** tab on the left sidebar.
2. Click **New query**.
3. Open the file [`/supabase/schema.sql`](./supabase/schema.sql) from this repository.
4. Copy and paste the entire content into the SQL Editor and click **Run**.
5. This creates all 9 tables:
   * `public.users` (synchronized with Supabase Auth)
   * `public.heritage_sites` (GIS coordinates, architectural status, visiting info)
   * `public.artifacts` (accession numbers, materials, provenance)
   * `public.inscriptions` (Brahmi scripts, Prakrit transcriptions, translations)
   * `public.virtual_tours` & `public.tour_stops`
   * `public.events`
   * `public.contributions` (citizen archaeology submissions & review status)
   * `public.favorites`
   * `public.archive_versions` (scholarly audit trail)
   It also enables **Row Level Security (RLS)** and defines security policies for all roles.

### Step 2: Populate Initial Heritage Records (Seed Data)
1. In the SQL Editor, click **New query**.
2. Open [`/supabase/seed.sql`](./supabase/seed.sql).
3. Copy, paste, and click **Run**.
4. This seeds authentic archaeological data for Phanigiri, Nelakondapalli, Kotilingala, and other Telangana Buddhist monuments.

## 4. Supabase Storage Buckets

The platform supports storing high-resolution artifacts, excavation photos, and audio guides across 8 storage buckets:

| Bucket Name | Purpose | Public Access |
| :--- | :--- | :--- |
| `site_photos` | Monument landscapes, stupas, and excavation aerial shots | Yes |
| `artifact_images` | High-res photos of toranas, sculptures, and coins | Yes |
| `inscription_images` | Brahmi stone slabs and copper-plate scans | Yes |
| `manuscripts` | Digitized palm-leaf & scholarly research manuscripts | Yes |
| `audio_guides` | Curated auditory narratives and site tours | Yes |
| `panoramas` | 360-degree gigapixel site captures | Yes |
| `models_3d` | GLTF/GLB photogrammetry models of antiquities | Yes |
| `contributions` | Uploaded citizen archaeology field photos & damage reports | Yes (Read) |

To create them in Supabase:
1. Go to **Storage** in the Supabase sidebar.
2. Click **New Bucket**.
3. Enter each bucket name from the table above and toggle **Public Bucket** to ON.

## 5. User Roles & Access Hierarchy (RBAC)

SanghaTelangana features 5 distinct user roles:

1. **Visitor**
   * Default role upon sign-up.
   * Public browsing of all sites, artifacts, and virtual tours.
   * Personal bookmarking & favorites.

2. **Contributor**
   * Can submit field documentation, photographs, and damage reports via `/contribute`.
   * Can view and track their submitted contributions in `/profile`.

3. **Researcher**
   * Privileged scholarly view of epigraphical transcriptions.
   * Access to the **Archive Versions Audit Trail** (`archive_versions` table) on `/archive`.

4. **Curator**
   * Access to the Curatorial Review Queue on `/profile`.
   * Can review, approve, or reject citizen submissions with scholarly evaluation notes.

5. **Admin**
   * Full database management, storage bucket inspection, and role administration.

> **Quick Testing:** Open the Sign-In modal (`Login / Join`) anywhere in the application and use the **"Quick Demo Role Switcher"** buttons to test any role instantly!
